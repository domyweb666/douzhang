# 交接（v0.1 暫定，方向未定）

## 給 3-4 feel（可以現在開工）
- 核心畫面的互動區：豆罐在三個方向都在畫面下半，離最下緣至少 34＋16 pt，離開始鈕留 16pt 以上，傾斜滾動與點彈的互動區不碰系統邊緣（3-3 怎麼做五）。
- 要在真機量的：本地通知在 app 被暫停／被結束後是否準時響；Live Activity 到點時能不能自己結束（流程查證 2026-10-31 未確認）；豆子入罐的延遲與掉幀；最舊支援機＋低電量模式。
- 鍵盤真實高度、鍵盤「完成」鍵送出（方向 C）在 SwiftUI 的行為。

## 給 3-5 tokens（等方向定）
- 版面尺寸全在 `線框/*.html` 的 CSS 裡，pt 直接可抄。
- 詞彙待樹狀測試與方向測試後定：豆棚、收據、翻到背面、收工、作廢、記一筆、這顆不留話。

## 環境事實（多米 2026-10-31：用 Expo Go，沒有 Mac／Xcode）

查證 2026-10-31（docs.expo.dev）：
- 灰盒子改用 **Expo（React Native）** 寫，在 iPhone 的 Expo Go 裡跑。系統鍵盤、安全區、動態字級（RN 的 allowFontScaling／maxFontSizeMultiplier）、觸覺（expo-haptics）、加速度計（expo-sensors DeviceMotion）、Skia 繪圖（react-native-skia，Expo Go 內建）都拿得到。haptics 與 sensors 是 Expo 第一方套件，照理在 Expo Go 內，⚪ 第一次跑時確認。
- **本地排程通知（鈴響、休息結束）在 Expo Go 可用** 🟢；遠端推播不行（豆帳不需要）。
- **Live Activity、主畫面小工具、控制中心按鈕在 Expo Go 不可用** 🟢：expo-widgets 需要 development build（EAS Build 雲端編譯，不需本機 Mac），且標 alpha。流程表已把這三項標「之後」，環境也剛好擋住，一致。
- 上架與真機完整版要走 EAS Build，雲端有 Mac，本機不需要。
- Expo Go 商店版支援的 SDK 版本會變（查證當天文件寫 54，較新文件提到 57），多米手機上的 Expo Go 支援哪版，開專案前先對。
- 單手檢查表的四個「待真機」項（鍵盤、最大字級、系統邊緣、大小手機）在 Expo Go 灰盒子上就能全部跑完，這步不再卡環境。
- 技術選型注意：React Native 是多米的環境給定，不是依 3-4 手感測出來的。豆罐物理（40 顆、碰撞、傾斜）在 RN 做得到多順，feel 要在最舊支援機＋低電量上量；量不過，退路是豆罐改簡化版，不是換框架。
