# 原型規格（v0.1 暫定，交 VibeRails）

## 範圍
一個畫面，兩件事：**豆罐**（N 顆豆、傾斜滾、點一下彈、碰撞聲與觸覺）與**一顆豆掉進來**（按一顆灰按鈕觸發，模擬「收下這顆」）。灰色單色。不做導覽、儲存、美術、計時、鈴響。
放在 `E:\豆帳\app`：加一頁「豆罐原型」，從灰盒子的除錯頁進；或獨立成 `app/Jar.js` 由除錯頁切換。正式版不從這份長出來（❓ 原型丟不丟，等閘門 3 再問）。

## 環境
Expo SDK 58，在 iPhone 的 Expo Go 跑（已查證：不需 Mac；Skia、haptics、sensors 在 Expo Go 內）。所有量測在真機；模擬器與電腦 web 模式的數字不算。

## 2-4 七條對應
| 條 | 這個原型怎麼做 |
|---|---|
| 1 延遲先於動畫 | 物理運算不能卡住畫面更新：三個候選技術（見下）都要量「傾斜到豆子開始滾」與「點下到豆子開始彈」的延遲 |
| 2 第一幀立刻動 | 點下去那一幀豆子就要有位移；傾斜平滑 0.15 造成的半拍延遲要量，必要時改成「第一幀直接跟、之後才平滑」 |
| 3 放手把速度交給彈簧 | 本原型沒有拖曳。對應成：點彈衝量與掉落初速進物理，不是播固定時長動畫 |
| 4 動畫可中斷 | 連續模擬，任何時候再點、再傾斜都從當下狀態接手 |
| 5 觸覺分型 | 入罐：事件型 `Haptics.impactAsync(Rigid)` 在落地那一幀。碰撞：事件型 `Light`，門檻與聲音同、最短間隔 90 ms。沒有連續型（Expo Go 沒有 Core Haptics） |
| 6 視聽觸同一事件 | 落地判定（b.y 觸底且 vy>門檻）同一處觸發：位移、啵、觸覺 |
| 7 尊重系統 | `AccessibilityInfo.isReduceMotionEnabled()`：開啟時掉豆改淡入、不滾、不彈、碰撞聲保留。靜音：跟系統靜音開關（expo-av 的 playsInSilentModeIOS 設 false）。觸覺關閉由系統處理 |

API 名稱查證 2026-10-31：expo-haptics `impactAsync(ImpactFeedbackStyle.Light|Medium|Heavy|Soft|Rigid)`、`notificationAsync`、`selectionAsync`（docs.expo.dev）。彈簧（reanimated `withSpring`，參數 damping、stiffness、mass、velocity，查證 2026-10-31 docs.swmansion.com）本原型用不到；候選 2 用的 `useFrameCallback` 與 reanimated 在 Expo Go 內建與否，查證未完成，第一次跑時確認。

## 隱藏調整面板
- 觸發：**長按豆罐標題 1 秒**。不用三指手勢（iOS 有三指點按叫出編輯選單，會撞）。
- 每個 B 類參數一條滑桿，即時生效；A 類的掉豆延遲、牆面恢復係數、傾斜平滑、點彈衝量、碰撞聲門檻優先。
- 面板上有「掉一顆」「掉一顆雙豆」「清空」「40 顆」「切 1 號／2 號參數組」（盲測用）。
- 滑桿元件：`@react-native-community/slider`（Expo Go 內建與否第一次跑時確認；不行就用 ＋／− 按鈕）。

## 互動區
豆罐底邊離螢幕最下緣 ≥ 50 pt（34 手勢區＋16），左右各 16；點彈的手勢只吃罐內。不佔頂部狀態列。

## 單指與 VoiceOver
豆罐是裝飾層，沒有任何資訊只在這裡：豆數同時以文字顯示在罐上方。VoiceOver 標籤「今天 N 顆豆」，自訂動作「彈一下」。傾斜可在設定關掉（原型有）。

## 三個技術候選（同一份規格、同一組參數、同一套量法；不寫優劣，只填對照表）
1. **JS 迴圈**：`requestAnimationFrame` 跑物理，豆子是 `View` 改 `transform`（原型的做法直接移植）。
2. **UI 執行緒**：`react-native-reanimated` 的 `useFrameCallback` 跑物理於 worklet，`@shopify/react-native-skia` Canvas 畫豆。
3. **現成物理**：`matter-js`（純 JS）算，Skia 畫。
每個候選都要在最舊支援機＋低電量＋40 顆＋大幅傾斜下量，表在 `技術選型決定-暫定.md`。
