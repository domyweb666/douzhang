## 必修

### R1 番茄架會當掉：同步把別的時區收的番茄帶進來
- `Core/RackCalendar.swift:113-120`（axisHours）、`:75-84`（dayBlocks）、`UI/RackTimeline.swift:29`（`axis.from ... axis.upTo`）。既有的洞，不是這批寫的；但同步以後變成一般人會碰到，壞檔也能觸發，正好打穿 `SyncLimits` 檔頭說的「不准讓這台每次打開都當掉」。
- 情境 A（正常使用）：A 手機在台北早上 8 點收一顆，格子是台北那天；B 手機在洛杉磯，番茄架看那一天（天檢視，或那三天、那週只有這種時段的番茄）。`DayKeys.start` 用這台現在的時區，top＝-8，算出 from 0、upTo -6，`0 ... -6` 直接當。反方向（洛杉磯晚上 8 點收、在台北看）是 `35 ... 24`，也當。只帶一支手機出國回看前幾天也會。
- 情境 B（壞檔）：雲端一筆沒有 tz、`t` 不是數字（補成 0），放在 `2026-11-24`：top 約 -49 萬小時，from 0、upTo 負數。SyncLimits 收 0 到 4e12，擋不到。
- 怎麼改：axisHours 夾住並保證 from < upTo，例如 `from = min(23, max(0, …))`、`upTo = max(from + 1, min(24, …))`；dayBlocks 的 top、end 都夾在 0...24。想畫對位置要再把時刻照那筆的 zone 換算，那是另一題。加測試：base 差 ±16 小時的一顆、`keptAt` 0 的一顆，斷言 from < upTo。
- 確定程度：高（算式照抄跑過）。

### R2 以前刪掉的預設標籤，會被另一台全新安裝帶回來
- `Core/SyncTags.swift:12-18`、`:31-42`；`Core/SyncFiles.swift:58`。
- 情境：v1（Expo）時期刪過 t3、t5，或當時的清單本來就沒有這幾個。v1 沒有 removedTypes，升到 v3 後「還在」與「刪掉」兩邊都沒有它的紀錄。買第二支手機、全新安裝、開同步：新手機的 tags.json 帶五個 mod 0 的預設，舊手機合完就多出 t3、t5。「已刪維持刪」只保護 v2 以後刪的。準則 5-24 寫的是「沒動過的預設不上傳、別台留下沒動過的不收」。
- 怎麼改：合併時，別台 mod 0 的「還在」的標籤，本機還在與刪掉兩邊都沒有這個編號、而且合完的 days 沒有任何一筆掛在它上面，就不收。「有紀錄用到就收」不能省，不然新手機用預設標籤收的番茄，在舊手機會變成「已刪除的標籤」。SyncTags.merged 要多收「用到的 typeId」。`SyncLawsTests.state` 的 mod 要改成 1 起跳（mod 0 不再交換），另加這條的測試。
- 確定程度：高（規則照跑一定發生；多米手上的資料有沒有這種，要看他的檔）。

## 值得改

### S1 標籤整個照一個 mod 比，兩台各改不同欄會丟一邊
- `AppState.swift:34`、`SyncTags.swift:55-73`。
- 情境：A 把 t2 改名「寫稿」。B 還沒拉完，在刻度尺把 t2 調成 40 分（`TimeDialScreen.swift:62`，很常做的動作），B 的 mod 比較晚：t2 整個照 B，名字變回「工作」，A 的改名不見。長度是天天動的欄、名字是使用者打的字，綁同一個時刻最容易出事。
- 怎麼改：趁 v3 還沒出貨，名字、長度、顏色各記一個時刻，合併一欄一欄比；刪除跟三個裡最晚的比。出貨後再改就要 v4。規格寫的是一個 mod，要主對話定。
- 確定程度：高（照規格就是這樣）。

### S2 第一次合併：兩台各自把同一個預設改成不同的意思，舊番茄會換名字
- 情境：兩支手機分開用了一陣子，A 的 t2 叫「寫稿」、B 的 t2 叫「剪片」。合完只剩一個名字，另一台那些番茄全部掛到錯的標籤；分不回來，只剩自動備份。兩邊都是 v2 升上來的（mod 都是 1）時，由「字比較大」決定，跟誰後改無關。
- 怎麼改：照規格可以不動，但要讓多米知道。要救就在第一次同步前，發現兩邊 mod 都 > 0 且名字不同時，先問或改配新編號（紀錄一起改）。
- 確定程度：高；發生機率低。

### S3 收下贏作廢時，作廢那邊打的字會不見
- `SyncJoin.swift:68-73`（absorbed）：作廢的 `text`、`doing` 直接丟。規格只寫念頭與有人找併進去，程式沒寫錯；但 `text` 是使用者打的一行字，違反「不丟原始紀錄」。
- 怎麼改：`next.clue = lines(bean.clue, entry.text)`、`next.doing = lines(bean.doing, entry.doing)`。這個改法我跑過 8000 組，六項性質照樣 0 錯。reason、minute 可以丟。
- 確定程度：高；發生機率低（同一顆在兩台都結束過才會）。

### S4 作廢分鐘超過一天、或負的，別台永遠收不到
- `SyncLimits.swift:12-15`。半頁開著放超過一天才按，或計時中手機時鐘被往回調（minute 變負）。這台有、別台沒有，還不會說。JA 自己有記。
- 怎麼改：minute 另給寬一點的範圍（例如 0 到 525600），超出的夾住而不是整筆不收；它只拿來顯示與倒推時間軸。
- 確定程度：高；發生機率低。

### S5 全被刪光留一個：各台留自己的，之後會突然不見
- `SyncTags.swift:82-88`。情境：A 剩 t2、B 剩 t1，各刪對方留的那個。兩台各自留一個，永遠不一樣。A 之後加一個新標籤，下一次合併 t2 就從清單消失、選中的也換掉。
- 怎麼改：留下來的那個把 mod 設成 `max(刪除時刻, mod)`，等於真的救回來：兩台最後都是兩個標籤，也不會再消失。跑過 5000 組（含全被刪光的資料）：現在的寫法有 313 組三台最後不一致，改完 0 組；只合一輪時兩台仍可能暫時不同。兩個都留比較安全，之後可以再刪。
- 確定程度：高。

### S6 測試名不副實：`SyncTagsTests.test沒記到刪除時刻的舊資料也維持刪`
- `SyncTagsTests.swift:47-50`：`removeType(now: 0)` 經過 `stamp` 變成 removedAt 1，測到的不是 0。`SyncTags.goneAt` 的「+1」與 `removedList:97-99`「照原樣留著」在 removedAt 0 時都沒有測到。
- 怎麼改：直接造 `RemovedTag(type: t2, removedAt: 0)`，兩個方向都合，斷言維持刪，且本機那份還是 0。
- 同類缺口：`SyncLawsTests` 的時刻全是整數，「本機帶小數＋內容又不同」沒有一則測到（我的模擬有測、沒錯）。把 base 加幾個 .25／.75 就補得到；比的時候要先取整。
- 確定程度：高。

## 小事（建議，不擋）
- `SyncFiles.swift:12` 日期鍵只看寫法：`2026-02-31`、`0001-01-01` 都收，沒時區的紀錄會一直留在那格（不會當，只是怪）。多驗一次「`DayKeys.dateOf` 再寫回來要一樣」，年限 2000 到 2099。
- `SyncLimits`：標籤 len 0 收得進來，開始就鈴響。標籤下限改 1，或對齊 1 到 90 的刻度再寬一點。
- 安全標準 I7：標籤名 20 字、那句 120 字，雲端讀進來不截（本機匯入也不截，同一個洞）。
- `SettingsLogic.removeType` 的 `now: Millis = 0` 預設值：現在只有測試在用。有同步之後漏傳，會記成 1970 年刪的，別台任何改動都讓它復活。拿掉預設值，三個時刻相關的函式就一致。
- `SettingsLogic.stamp`＋`cloudTimes`：壞檔給 mod 4e12，這台再改就超過上限，別台永遠不收。機率極低。
- `len` 不是二分小數（例如匯入檔的 33.3）時沒取整，JSON 來回理論上可能差最後一位，會多寫一次，但合併會收斂，不會互寫。
- 併出來的 `doing` 有換行（「寫稿」「改稿」兩行），分析與月清單照整串當一個名字，另成一項；少見，畫面沒看過。
- `SyncFiles.remotes` 比自己編號時分大小寫：`UUID().uuidString` 一律大寫，現在沒事；比的時候都轉大寫更穩。

## 逐項對過、沒問題的
- 帶小數的本機：同一份留本機那份；內容不同但排名相同也留本機的小數；`doneAt` 取大會留小數。合完再合不變。存檔再讀差最後一位、剛好跨過整毫秒時，最多多寫一次，不會來回。
- 沒時區的舊紀錄：鍵只會往最早的那個走，不會一直往前；收下對作廢照收下那邊。新時區名在舊系統認不得時照檔裡的鍵，不會跳。
- 全新安裝的 mod 0 蓋不掉改過的；v2 以後刪掉的不復活；刪與改差不到一毫秒照 goneAt 補一毫秒，結果固定。
- 路徑：UUID 來回、`\z`、兩段、月 01 到 12，換行與 `..` 都擋；大小、版本、型別、布林當數字都有擋；NaN／無限大進不來，`JSONSerialization` 不會丟 ObjC 例外。
- v1／v2 讀進 v3：預設判斷含顏色長度；`t`＋13 位數；全形數字轉不成 Double 會落到 1。舊版讀 v3 只是不認得 mod。存成 v3 回舊版再升，mod 會退回（0、建立時刻、1），提案已列為不能還原。
- 照 `id` 補的編號：同一份舊檔兩台一樣。
- 包 A、E1 的回報跟程式對得上，沒有寫了沒做的。
