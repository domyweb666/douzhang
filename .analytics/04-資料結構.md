# 番茄帳｜04 資料結構與邊界情況（v1.0，閘門 2 已過 2026-11-22，程式已寫、雲端全綠，手機沒看過）

> 2026-11-21。舊 app 插隊先做這一步：每晚一天就多一天補不回來。
> 多米確認（閘門 2）之前不寫程式。問題清單（3-1）還沒過閘，所以這份只收「現在不存、以後補不回來、而且全自動零成本」的東西；要使用者多按一下的欄位一個都沒加。
> 書的原則用 ⚪ 標的是起點數字，不是定律。

## 現在的格式（v1，Expo 版與 SwiftUI 版共用）

一個 JSON：`v`、`settings`（含 `types` 標籤清單）、`current`（進行中那顆）、`days`（鍵是 `YYYY-MM-DD`，裡面 `beans` 收下的、`voids` 作廢的）、`lastLine`。

查到三件會影響怎麼改的事：

1. **兩個版本讀檔都只留認得的欄位，其他丟掉**（Swift `StateDecoding.normalize`、Expo `store.js`）。所以新欄位 Expo 版讀得進去、不會壞，但資料只要回 Expo 版存過一次，新欄位就沒了。
2. **兩邊匯入只檢查 `v` 是數字**，不看是幾。升到 2 不會被擋。
3. `days` 的鍵是收下那一刻照手機時區、午夜切出來的「開始那天」。這是算出來的東西，但對沒存時區的舊資料，它反而是當時當地日期唯一的紀錄。

## 六條原則：改完之後的樣子

| # | 原則 | 現在 | 改成 |
|---|---|---|---|
| 1 | 只存原始紀錄 | ✅ | 不動 |
| 2 | 世界標準時間＋當時時區 | 沒有時區 | 每顆、每筆作廢、進行中那顆各加 `tz`（開始那一刻的時區名，例如 `Asia/Taipei`） |
| 3 | 不覆寫、刪除用標記 | 刪標籤直接拿掉 | 刪掉的標籤搬到 `settings.removedTypes`，不丟 |
| 4 | 每筆有編號 | 番茄、作廢沒有 | 各加 `id` |
| 5 | 計時不靠 app 開著 | ✅ | 不動 |
| 6 | 版本號 | `v: 1` | 升 `v: 2` |

## 事件結構（v2；粗體是新加的）

收下的一顆（`days[日期].beans[]`）：

```json
{
  "id": "新：每顆自己的編號",
  "t": 1795262400000,
  "start": 1795260900000,
  "tz": "新：Asia/Taipei",
  "typeId": "t1",
  "len": 25,
  "flow": 0,
  "done": "新：true＝計時中按過「提早做完」；沒按就不寫這欄",
  "doneAt": "新：按「提早做完」的時刻；沒按就不寫",
  "clue": "收下時寫的那一句",
  "notes": ["計時中記的念頭"],
  "pings": ["計時中記的有人找"]
}
```

作廢的一筆（`days[日期].voids[]`）：

```json
{
  "id": "新",
  "t": 1795261500000,
  "start": "新：開始時刻（現在只有第幾分鐘，倒推會差到一分鐘）",
  "tz": "新",
  "typeId": "t1",
  "len": "新：這顆原訂多長",
  "minute": 10,
  "reason": "念頭｜訊息｜卡住｜其他｜空字串＝沒選",
  "text": "選填那一行",
  "notes": "新：這顆作廢前記的念頭",
  "pings": "新：這顆作廢前記的有人找"
}
```

刪掉的標籤（`settings.removedTypes[]`，新）：

```json
{ "id": "t7", "name": "剪片", "len": 50, "color": "purple", "removedAt": 1795262400000 }
```

進行中那顆（`current`）：加 `tz`、`doneAt`，收下或作廢時抄進去。

**為什麼刪掉的標籤另外放一個陣列，不在 `types` 裡加已刪除標記**：Expo 版不認得那個標記，會把已刪的標籤當成還在。另外放，Expo 版頂多看不到它，行為跟現在一樣。

**順帶發現的一個洞（不只是分析的事）**：現在作廢一顆，那顆計時中記的念頭與有人找會跟著消失，`VoidEntry` 沒有這兩欄。上面的結構補上了。

## 舊資料怎麼轉（v1 → v2）

SwiftUI 版第一次讀到 `v: 1`：

1. 每顆番茄、每筆作廢補一個 `id`。
2. 不補 `tz`、`done`、作廢的 `len` 與 `start`：不知道的就留空，不猜。
3. `removedTypes` 從空的開始。
4. 存成 `v: 2`。
   - **實作時改了一點**：沒有另外做「轉之前自動備份」。理由：沒有任何手機上有 SwiftUI 版存的 v1 檔（它還沒上過手機）；第一次打開是從 Expo 的存檔讀進來，那份原始存檔不動，就是升級前的那一份。匯入舊備份的路本來就會先自動備份。
   - 補編號不是「轉一次」，是每次讀檔都照同一個算法補，所以還沒存檔前讀幾次結果都一樣。
5. Expo 的原始存檔照舊不刪。

跟 `OVERNIGHT.md` 待確認那一條有關：已拿掉的功能留在檔案裡的舊欄位（`planted`、`tasks`、`closed`、`leaf`…），Swift 版現在是讀了就不寫回去。照「不丟原始紀錄」的原則，建議原樣帶著不丟。這條還是多米定。
